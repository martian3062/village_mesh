# Published Unreal assets with Git LFS

The repository includes the saved V1/V2/V2.5/V3 village assets, the separate Pardeep third-person village, their World Partition actors/objects, the generated Manpreet MetaHuman, pinned CC0 source textures/vegetation, and runtime data/fonts. The current snapshot contains **8,774 files / 1,268,762,134 bytes**. Of these, **8,756 files** use LFS. Duplicate content is stored once by LFS, so uploaded storage can be smaller than the file total.

The largest file is `Content/MetaHumanPilot/Characters/MH_Manpreet.uasset` (144,130,040 bytes). It is stored as an LFS object; Git contains its small pointer. Existing history is preserved without a migration or force push.

## Clone and open

Install [Git LFS](https://git-lfs.com/), then run:

```powershell
git lfs install
git clone --recurse-submodules https://github.com/martian3062/village_mesh.git
cd village_mesh
git lfs pull
python Scripts/lfs_publication.py verify
```

For an existing checkout, run `git lfs install`, `git pull --ff-only` and `git lfs pull`. Opening the project before LFS downloads finish will leave pointer text where Unreal expects binary assets.

Use a licensed Unreal Engine **5.8.4** installation to build `rural_pardeepEditor`. The MetaHuman pilot and temporary Pardeep player also require **MetaHuman Creator Core Data** and the project-enabled plugins. Engine/plugin dependencies remain external, including Epic's neutral idle, walk and run clips. See the [pilot setup guide](../MetaHumanPilot/README.md). The editor now starts on `/Game/VillageMeshV3/Lvl_PandoriV3_Pardeep_WP`; use `Scripts/pardeep_village.ps1 -Action Play` for the third-person world. The previous V3 map remains available. No new packaged release is included.

Epic's [current MetaHuman FAQ](https://www.metahuman.com/license) permits packaging created MetaHuman assets for distribution through Fab and third-party marketplaces; the [Unreal Engine EULA](https://www.unrealengine.com/en-US/eula/unreal) still governs Epic technology and its restrictions. Publication here does not grant MIT rights to Epic material or permit using MetaHuman assets for AI training/testing. The Kaggle job remains limited to synthetic numeric controller states.

The old imported `Content/Village` assets and unrelated template content are excluded because their provenance has not been established for this publication. Credentials, raw logs, `Saved`, caches, generated executables, engine binaries and the full Creator Core Data library are excluded. The repository is not a backup of every local file.

## Verification and future asset updates

The read-only Unreal dependency audit checked **8,724 packages**, including hard/soft references and World Partition packages, with no missing or excluded project dependencies. Required installation mounts are listed in the manifest. This verifies saved package references; it is not a new clean-machine play or package test. The separate local third-person movement check is documented in [the player guide](../PardeepPlayer/README.md).

Run the audit using the installed editor commandlet, then prepare and verify a new snapshot:

```powershell
& 'E:\U.E\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe' "$PWD\rural_pardeep.uproject" -run=pythonscript "-script=$PWD\Scripts\audit_lfs_assets_unreal.py" -NullRHI -unattended -nosound
python Scripts/lfs_publication.py prepare
python Scripts/lfs_publication.py verify
git add --pathspec-from-file=Saved/LFS/asset-paths.txt
git lfs status
```

Review licenses and diffs before staging an updated manifest and committing. New download files must match a pinned source hash; unrelated directories and traversal paths are rejected. Only saved on-disk assets are captured. Unsaved editor changes are not included. Do not remove the ignore rules for the entire `Content` tree.

GitHub's [LFS documentation](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage) explains pointers and plan-dependent file limits. The client uses the configured account's LFS service; no paid plan or billing setting is changed by this workflow.
